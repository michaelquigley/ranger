## npm audit, round two: brace-expansion

Four new high-severity findings, one real advisory: `brace-expansion` <=5.0.7 (GHSA-mh99-v99m-4gvg, DoS via unbounded expansion) through the same redocly chain as the js-yaml episode — minimatch 5.1.9 exact-pinned by `@redocly/openapi-core` 1.34.17 under `openapi-typescript`, dev-tooling only, nothing ships. npm's suggested `audit fix --force` was a *downgrade* to openapi-typescript 6.x; declined. Upstream still hasn't moved (openapi-typescript 7.13.0 remains latest, on redocly 1.x), so: a second scoped override, `minimatch.brace-expansion` → 5.0.8, the only patched release.

The override jumps majors, so it was verified rather than assumed: audit 0; `gen:api` byte-identical; 40 UI tests + build green; and the export-shape edge was hunted deliberately — brace-expansion 5.x exports `{ expand }` named while minimatch 5.1.9 calls the module as a function, so a brace-containing pattern would throw loudly ("expand is not a function"). Redocly's actual call (`minimatch(url, pattern)`, plain path/URL patterns; no redocly config exists in the repo) never constructs one — canary-checked both ways. Overriding minimatch itself to a patched 10.x was rejected on the same class of evidence: redocly calls the module as a function, and minimatch 10's CJS export is an object.

The `drop-the-js-yaml-override` roadmap item (now ranked on horizon — filename untouched, order.yaml is Michael's) had its body extended to cover both overrides, the accepted brace-pattern edge, and the added trigger (a brace-expansion 2.x backport frees that override independently). Title now reads narrow; a retitle through the modal is Michael's call. No changelog (no behavior change), no terminus (no product code).
