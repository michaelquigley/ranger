# 2026-07-23 — the open modal rides the clock

Michael's follow-on to live reload: an open item modal should re-render when its card's content changes underneath it. No second poll — the board poll is the clock and the card's `hash` (already on every wire card) is the change signal. `shouldReloadItem` in `src/live.ts` is the pure decision: reload when the fresh board's hash for the item differs from the loaded one, *suspended* whenever operator input is in flight — raw edit, an active retitle, a delete confirm, or a shown collision notice — because in-flight input is never stomped and the hash guard owns any conflict at save. A card the board no longer carries (deleted or renamed elsewhere) reloads too, surfacing the plain 404 panel rather than presenting stale bytes as current. `App` passes `boardHash` via a `hashOf` helper beside `locate`; the modal's effect applies the decision.
