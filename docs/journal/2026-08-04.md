# 2026-08-04 — saved filters land

The `saved-filters` card, single-agent end-to-end. The card's spike was really one seam decision — where saved filters live — and Michael called it in one line: `docs/future/roadmap/.ranger/filters.yaml`, because saved filters "want to be published into the actual work alongside the cards." That call turned a would-be localStorage feature into a full-stack one: document layer, workspace, API, UI.

## the design

- **`.ranger/` is a new thing in the roadmap directory**: a tool-state subdirectory — not items (subdirectories never hold items), not assets. The convention note's Recognition section now names it.
- **filters.yaml is the third document kind and the first that is tool-rendered.** Items and order.yaml are operator-authored bytes the tool patches surgically; a filters file is born from a board gesture, so `RenderFilters` re-emits the whole document on every save — deterministically, by hand-built strings, never a YAML encoder, so the no-encoder rule holds. Hand edits are honored on read and re-canonicalized on the next save. Format: `filters:` list, snake_case keys (dd's default binding), flow-style lists matching card frontmatter, empty dimensions omitted.
- **Whole-set replace as the one mutation.** `PUT /projects/{project}/filters` carries the full resulting set plus `expectedVersion` — one endpoint, one write path, and upsert/delete are client-side list operations. Guard semantics mirror order.yaml exactly: hash version, `absent` sentinel, `CompareAndWrite` no-clobber creation, 409 `filters_conflict` (new conflict reason, third member of the reloaded-notice family).
- **Filters ride the board payload** (`savedFilters` + `filtersVersion`), so the live-reload clock keeps the pills fresh from any hand and there's no second fetch path. `freshest` is a JSON deep-compare, so the new fields participate in identity preservation for free.
- **Degradation tier is softer than order.yaml's**: an unreadable filters.yaml leaves both board fields absent — pills and save affordance vanish, board sails on. A broken lens must not take down the board it views. `ParseFilters` itself reads whole-or-not-at-all (empty/duplicate names refuse, like duplicate lane keys) because a filter without a name has no identity to degrade to.
- **UI**: saved pills in the header (`saved:` row) — click applies the set as the whole active filter, `×` deletes without confirm (one line in a reviewable file; item-delete's confirm guards a whole card, different stakes). `save` in the filter bar opens an inline name input, Enter commits, Escape/blur cancels — the retitle-in-place pattern. Same-name saves update in place, preserving list position. The search query is deliberately not part of a saved filter.

## follow-up: active pill highlight

First soak feedback, same day: when a saved filter is applied, its pill should say so. The design call was *how* active is known — remembered ("last clicked") or derived. Derived won: `isApplied` compares the live filter state against each saved filter, per dimension as sets (order aside), so the highlight can't lie. Edit the filter past the saved shape and it drops; rebuild the same lens by hand and the pill lights; two identically-shaped saved filters both light, which is the honest answer. No new state, and live-reload keeps the comparison fresh for free because the pills already ride the board payload. Rendered as an accent-blue border and text (`.saved-active`), the same interactive-emphasis blue as button hover and links — quiet, in the spirit of the header-pill-quietness soak question. Title flips to "{name} is applied." Search stays outside the comparison, as it stays outside the saved filter. Two new filter tests (62 total in the UI suite), `make build` green. Docs threaded: `ui-and-serve.md` saved-filters bullet, CHANGELOG's unreleased saved-filters entry, a log line on the card.

## "no" filters land

The `no-filters` card, same-day capture to built. The feature: filter cards where a dimension (tags, subsystems, milestone) is not specified at all — the triage lens the not-filters can't express, since excluding a value names a value and absence has none.

- **The design fork was where the gesture lives**, because absence has no chip to click. Alternatives weighed: ghost chips on cards (consistent, but permanent ink to serve a rare gesture), a standing header control / facet panel (standing chrome; the fuller version is its own much bigger card), convention-first with no gesture (hand-authored yaml only — a subset of what was built, not really a rival). Michael called `no:` in the search box.
- **Entry gesture, not home.** The critical cut: `no:milestone` typed into the search box does not become search syntax — `recognizeNo` plucks complete tokens out of the input and compiles them into ordinary filter state, exactly as if a chip that doesn't exist had been clicked. Remaining text stays a plain search, untouched (spacing included) unless a token fired. Had absence lived *in* the query it would sit in the one gesture deliberately excluded from saved filters — and "unmilestoned backlog" is precisely a lens you'd save. This way absence filters compose, save, highlight, and live-reload with zero extra machinery.
- **Dimension-level, not value-level.** Three booleans on `BoardFilters` (`noTags`/`noSubsystems`/`noMilestone`), matching `no tags at all`, not `not tag x`. Displacement both ways in the polarity-flip spirit: toggling absence clears the dimension's includes and excludes whole; any value click clears absence. Contradictory states are unreachable by gesture; a hand-authored contradiction just matches nothing, honestly.
- **Tokens are the frontmatter spellings**, exact: `no:tags`, `no:subsystems`, `no:milestone`. Reserved words in the search vocabulary — the convention is primary, so the dimension names are the keys the operator already writes.
- **Full stack ride-along:** savedFilter gains three optional wire booleans (`noTags` etc., present only when true), filters.yaml gains `no_tags`/`no_subsystems`/`no_milestone` via `renderFlag` (emitted as `true` or omitted — false is the absent default), `wireFilter`/`docFilter` map them, dd binds them on read for free. Rendered pills are dashed-border (`.no-pill`) — the outline of the missing thing.
- **Deferred:** the mirror predicate (`has:milestone`) and the wider query language (`tag:epic`) — the recognizer seam admits both without rework; each is its own card if soak asks for it.

Verification: 68 UI tests (6 new: displacement both ways, recognizer pluck/keep semantics, absence save round-trip, board matching), Go document + server suites extended (absence parse, render round-trip, over-the-wire lifecycle with on-disk check), vet + `make build` green. Live smoke against `ranger serve` over a scratch workspace: absent → save with `noTags`/`noMilestone` → file bytes exactly `no_tags: true` / `no_milestone: true`, board round-trips the flags. Docs: filtering bullet in `ui-and-serve.md`, filters-document paragraph in `document.md`, PUT bullet in `api.md`, CHANGELOG FEATURE.
