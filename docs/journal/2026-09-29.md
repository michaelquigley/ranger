# 2026-09-29 — dirty projects first

The `dirty-projects-first` card, single-agent. The sort lives in the UI's pure model (`selectorOptions`), not in the server's `Index`: the wire index stays in config order because ordering is a presentation choice for one control, and the server has no reason to know how the dropdown wants its list. Stable sort on the dirty flag only — availability doesn't enter, so an unavailable-but-dirty project still rises (it's still uncommitted work), and the unknown-current phantom entry still unshifts to the top after the sort because it's the URL's truth, not a project.

Michael asked for a separator between the halves; native `<select>` offers `<optgroup>` or a fake disabled rule option, and the optgroup won because it's the only form where a screen reader and the visual list agree on what the grouping means. The groups only appear when both halves are non-empty — a wholly clean index (the common state) renders exactly as before, so nobody pays the labels for nothing. The flat `selectorOptions` survives as the flatten of `selectorGroups` so the order tests keep pinning top-to-bottom order without knowing about groups.

Terminus advisory, accepted: the second group was labeled `committed`, which asserts cleanliness for projects whose verdict is absent (git couldn't answer). Renamed to `other`, then to `projects` on Michael's call — a plain noun rather than a remainder word; a third `unknown` group was considered and dropped as chrome for a state that in practice means a root outside any repo.
