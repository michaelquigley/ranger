Design and planning session on `docs/future/ranger-v2.md`. The decisions are in that document under "The first design". This entry holds what the document does not say.

## mercurius round 1

`needs_changes`, six blocking findings and three advisory notes, all triaged with Michael one at a time. Seven were fixed in the documents. Two calls are not visible there:

- **The status read's index refresh stays as v1 runs it.** The reviewer found that `git status` refreshes the index's cached stat information, which writes inside `.git`, and proposed `--no-optional-locks`. Michael called it borderline over-hardening: v1 has polled this way for four months without trouble. Rejected, with the guard `status-read-index-refresh`. Do not add the flag as a tidy-up.
- **A rename between two items marks only the destination.** Half of the git-mapping finding was taken (an item is new when its `index.md` is untracked; any other untracked file is an unstaged change). The rename half was skipped as a corner case, with the guard `git-rename-attribution`.

Also decided in triage: Inbox ignores the view files, so an item moved back to Inbox keeps its lines and returns where it was if triaged again, in preference to a three-file write that would strip them. The five new CLI command names are reserved first words in every project, v1 included, recorded in the spec as the one v1 change; a quoted title still captures.
