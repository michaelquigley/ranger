# 2026-08-14 — order.yaml moves into .ranger/

The `orderyaml-rangerorderyaml` card, single-agent end-to-end. Small in code, load-bearing in convention: the ranking sidecar moved from `docs/future/roadmap/order.yaml` to `docs/future/roadmap/.ranger/order.yaml`, beside the saved filters.

## the design

The opening objection was that the card contradicted the convention as written. `.ranger/` was defined as *tool state* — "the file is tool-rendered, so agents leave it to the tool, the same way they leave `order.yaml` to the operator" — using order.yaml as the explicit contrast case. Moving the operator's hand-tended, comment-carrying, surgically-patched file into a directory defined by tool-renderedness makes the note argue with itself.

Michael dissolved it with a fact about practice rather than a fix to the framing: order.yaml is *never or rarely* hand-edited — it's manipulated through the board. So `.ranger/` isn't "tool state" versus "operator files," it's **ranger's own files**, and authored-vs-rendered stays a per-file property (patched vs. re-emitted) rather than a property of the directory. That definition costs one sentence in the convention note and is truer than what it replaces.

The second fork was migration, and my recommendation lost. I argued for a hard cut with hand `git mv` plus a loud error, on the grounds that a permanent read-both compat surface is exactly the corner-case defensiveness the posture vetoes. Michael's call: **ranger notices and migrates automatically**. He's right, and for a reason my framing missed — I was weighing "compat path forever" against "one-line instruction," when auto-migration is neither. It's a one-time forward move with no lasting compat surface at all: after it runs, the file has exactly one home and no code reads the old location.

Where the migration happens settles the rest. It runs at the top of `Load`, not on the write paths, because noticing has to happen where reading happens — confining it to writes would leave a read-only board un-ranked until someone dragged something. Steady-state cost is one `Lstat` per load. `.ranger/` is created only by the two writes that put files in it, so a roadmap with neither ranking nor saved filters never grows a directory it has no use for.

Design consequences recorded rather than assumed:

- **A read now mutates the filesystem.** `ranger list` on a legacy roadmap moves a file. That's inherent to what was asked for, and it stays a working-tree write under the git gate — but it's the one write ranger performs unprompted, where every other write expresses an operator gesture. Named as such in the code, `docs/current/`, and the changelog.
- **Migration failure is repository-level**, the same tier as an unreadable order.yaml. One branch, no fallback read of the legacy location. A board that can't complete the move is a broken roadmap, and in the daemon it degrades per project rather than taking anything else down.
- **Order writes go through one funnel** that creates `.ranger/` first, so a first-ever ranking is never refused for want of a directory rather than for want of a guard match.

## terminus

Round one (`b239cec2ef27`): **not clean**, one blocking finding, and a good one. `surgical-order-migration-rename` caught that I'd checked the destination with `os.Stat` and then called `os.Rename` — which on Unix silently *replaces* an existing destination. My own doc comment promised "an existing destination wins untouched," so the code contradicted the prose. I'd reasoned about the race in the wrong direction: I handled the source vanishing under a concurrent loader ("losing the rename is success") and never considered the destination appearing, which is the direction that loses data.

The fix was a simplification, not armor — `document.FinalizeLink` already exists and is exactly this primitive (link-then-remove, atomic refuse-if-exists). Using it *deleted* my separate destination check instead of adding to it, and non-regular entries fall out for free since `link(2)` refuses a directory. Same shape as 08-04's `df-binding-001`: hand-composing what the substrate already provides. Collision and a vanished source are both swallowed as success — the ranking arrived, whichever hand put it there.

Round two (`ca8c6661ad49`): **clean**, zero findings.

## verification

Go suite + vet + `make build` green. Three new migration subtests (bytes cross verbatim with comments intact and ranking preserved; an existing `.ranger/order.yaml` wins with the stray legacy file left byte-for-byte; a roadmap with no ranking never grows a `.ranger/`), plus a repository-tier subtest for a migration that can't complete. Existing fixtures across `gesture_test.go`, `workspace_test.go`, and `server_test.go` moved to the new path — the whole-tree diff suite caught every one of them itself, which is the fixture suite doing its job.

Live smoke: a scratch repo with a hand-tended legacy order.yaml (inline comments, a "do not reformat" header, ranking that contradicts created-date order) — `ranger list` migrated it, ranking honored, bytes byte-identical, and `git status` reported `R old -> new` once staged. A second scratch confirmed the wire path: board GET on an unranked roadmap left the tree alone and reported `absent`, then a `PUT /order/inbox` with `expectedVersion: absent` created `.ranger/` and the file.

**Dogfood caught an operational hazard worth remembering.** Mid-session, `make build` replaced the running daemon's binary out from under it — pid 39124 had been up since Aug 9, so the live board was serving *pre-change* code while the installed binary was new. Deliberately did not let the new binary touch this repo's roadmap in that window: migrating order.yaml under a running old daemon would have left it writing the legacy path on the next drag, splitting the ranking across two files. Michael restarted the daemon and it migrated cleanly on startup — `R docs/future/roadmap/order.yaml -> docs/future/roadmap/.ranger/order.yaml`, ranking intact. The general shape: **a path migration plus a long-lived daemon means the daemon has to be restarted before anything else runs the new code.**

## close-out

The OpenAPI source got the one description that could send a client to the wrong path, regenerated for three lines of churn. CHANGELOG CHANGE entry.

The grimoire's roadmap-convention note takes the `.ranger/` redefinition and the new path. Card matured to `evaluating` through the tool rather than by hand, so the order.yaml side stayed the tool's — soak questions about whether an unasked-for write should be visible somewhere, and whether the widened `.ranger/` definition holds as the directory gains anything else. Nothing committed; the working tree is the review queue.
