# 2026-08-03 — "not" filters land

The `not-filters` card ran single-agent end-to-end: below the pipeline threshold (client-side UI, no schema, no API, no convention contact). The spike dissolved at the first read — React mouse events carry modifier booleans and the chip handlers already receive the event — so the card's open question was really a design choice, not a feasibility one.

## the design

Michael picked **alt-click = exclude**. Ctrl-click was rejected outright: on macOS it's the context-menu gesture and browsers fire `contextmenu` instead of `click`, so the handler never sees it. Shift-click works but conventionally means extend-selection. The model, settled in conversation before any code:

- Every filter dimension gets polarity — tags, subsystems, *and* milestone. Plain click includes (unchanged), alt-click excludes.
- A value clicked into the opposite polarity **flips rather than stacking** — nothing is ever both required and excluded.
- The milestone keeps its single-select shape across both polarities: one slot, either sign. Excluding a milestone keeps unmilestoned cards — the exclusion names a train, not the absence of one.
- Excluded pills read `not x` in the header filter bar; click still removes; `clear` clears both polarities. Plain text, no new CSS.
- Search negation deliberately out — that's query-syntax territory, not a chip gesture.

## the shape

Filter logic moved out of `App.tsx` into a new pure module `ui/src/filter.ts` + `filter.test.ts`, following the house idiom (`reorder.ts`, `selector.ts`, `live.ts` — pure logic beside its tests, wiring in App). `filterBoard` was arguably the outlier living inline; now it's tested. The three filter `useState` hooks collapsed into one `BoardFilters` object with pure transition functions (`toggleTag`/`toggleSubsystem`/`toggleMilestone`, each taking an `exclude` boolean), which also shrank the dependency arrays. `LaneColumn` handler props grew the boolean, fed by `e.altKey`; chip tooltips say `(alt-click excludes)`.

The drag-under-filter path needed nothing beyond the signature change — placement was already anchor-based against the displayed lane, and the displayed lane is just filtered by a richer predicate now.
